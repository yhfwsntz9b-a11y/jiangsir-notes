同一套骨架，六种形态

六个变体都沿用同一张基准图：外部调度层 → Agent 业务层 → Agent 运行时 → 结果输出层。 变的只是“能力模块落在哪一层”。琥珀虚线标出本图新增或变化的部分，其余都是基准骨架。

外部调度层APScheduler：何时跑
Agent 业务层Job 函数 / 调用 / 回调
Agent 运行时循环壳 + 推理 + 工具 + 上下文
结果输出层落库 / 通知 / 日志
琥珀虚线 = 新增 / 变化 实线 = 调用与数据流 绿色 = 反馈回路

六种形态

01 / MEMORY新增层

有记忆的 Agent

短期记忆挂 Checkpointer、长期记忆进 Store；真正难的是写入治理，而不是把聊天记录塞回 Prompt。

CheckpointerStorethread_idTTL
打开变体 01
02 / RAG新增层

有知识库的 Agent

知识库是工具，不是记忆。离线入库、在线检索，Agent 通过 knowledge_search 拿到片段与出处。

knowledge_searchchunkrerankpre-filter
打开变体 02
03 / HUMAN-IN-THE-LOOP新增层

带人工介入的 Agent

危险动作先 Interrupt 挂起，状态落 Checkpointer；人审批后 resume，而不是让 Agent 原地等。

interruptresume审批粒度超时拒绝
打开变体 03
04 / REFLECTION运行时内

带反思的 Agent

Actor 出草稿，Critic 按 rubric 挑错，验收门决定回炉还是放行；关键是独立视角和退出条件。

Criticrubricmax_rounds验收门
打开变体 04
05 / PLAN-AND-EXECUTE运行时内

Plan-and-Execute

Planner 只规划，计划写成状态；Executor 逐步执行。经典实现不会自动重规划，Replanner 是额外节点。

Planner计划状态Replannermax_steps
打开变体 05
06 / MULTI-AGENT运行时内

多 Agent

Supervisor 分派，Worker 各自带 Prompt、工具、权限和上下文；共享状态，但不共享脑子。

SupervisorWorker共享 Statemax_turns
打开变体 06
看图顺序：先看 00 基准图建立骨架，再按需看变体。前三种（记忆、知识库、人工介入）是在骨架外新增一层； 后三种（Reflection、Plan-and-Execute、多 Agent）主要改运行时内部的图结构。
一句话：框架提供的是循环壳；记忆、检索、审批、反思、规划、多 Agent，都是在这层壳上加状态、加节点、加协议。
